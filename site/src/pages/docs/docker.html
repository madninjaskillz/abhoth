Self-host with Docker

Run Abhoth next to your GPUs and use it from any browser. The image runs the web UI in sign-in mode and keeps everything it writes in two folders.

What's in the image

A release build of abhoth (headless, without the desktop feature) on a Debian-based runtime. It also includes the .NET SDK, Node, Python, git, ripgrep and the Claude Code and Codex CLIs, so agents can build and test common projects, and you can switch a project's engine.

Build it

git clone https://github.com/madninjaskillz/abhoth
cd abhoth
docker build -f deploy/docker/Dockerfile -t abhoth-web .

Run it

services:
  abhoth:
    image: abhoth-web
    restart: unless-stopped
    ports: ["8093:8093"]
    environment:
      PORT: "8093"
      ADMIN_USER: admin                 # created on the first start
      TRUSTED_PROXIES: "172.18.0.1"     # your reverse proxy; X-Forwarded-* only from it
      REQUIRE_2FA: "0"                  # 1 = a code at every sign-in
      BENCH: "0"                        # 1 = the Benchmarks page
      OPENORCA_PROJECT_ROOTS: "Projects=/projects"
    volumes:
      - ./projects:/projects
      - ./state:/state
      - ./secrets/admin-password:/run/secrets/admin-password:ro
      # - ./secrets/git-deploy-key:/run/secrets/git-deploy-key:ro
      # - ./secrets/git-credentials:/run/secrets/git-credentials:ro
    read_only: true
    tmpfs: ["/tmp:size=2g,mode=1777"]
    cap_drop: [ALL]
    security_opt: ["no-new-privileges:true"]
    mem_limit: 8g
    healthcheck:
      test: ["CMD", "curl", "-fsS", "http://127.0.0.1:8093/api/auth/state"]
      interval: 30s

The repo's deploy/docker/compose.yaml is a fuller example, including an NFS projects share. Adapt the volumes, ports and secrets before you use it.

Folders and secrets

Path in the containerWhat
/projectsYour projects; new ones go in /projects/workspace by default.
/stateAbhoth's state home in /state/openorca (config, sessions, accounts; the name is kept for compatibility) and the container user's home in /state/home.
/run/secrets/admin-passwordWith ADMIN_USER, creates that admin on the first start. It's ignored once accounts exist.
/run/secrets/git-deploy-keyOptional: an SSH key for git.
/run/secrets/git-credentialsOptional: a git credential-store file.

The entrypoint never prints a secret. Set the model server's base URL and key in Settings after you sign in, or in /state/openorca/config.json.

The container runs as UID 568, GID 568. Make ./projects and ./state writable by that user, for example with sudo chown -R 568:568 projects state.

Accounts from the command line

docker exec -it <container> /app/entrypoint.sh admin create <name>
docker exec -it <container> /app/entrypoint.sh admin reset-password <name>
docker exec -it <container> /app/entrypoint.sh admin list

HTTPS

The container speaks plain HTTP and refuses it from anywhere but itself, so put a reverse proxy in front (Caddy, nginx, Traefik) that terminates TLS and forwards websockets. Set TRUSTED_PROXIES to the proxy's address so the forwarded scheme and client IP are believed from that proxy only. Cookies are __Host- prefixed and Secure over HTTPS.

# Caddyfile
abhoth.example.com {
  reverse_proxy 127.0.0.1:8093
}

Upgrading and rolling back

Rebuild the image from a newer checkout and recreate the container; the state formats are stable. An existing OpenOrca container's state works as it is, because OPENORCA_HOME is still honoured. To roll back, point the service at the previous image.
