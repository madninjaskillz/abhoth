Coming from OpenOrca

Abhoth is OpenOrca, rewritten in Rust and renamed. The C# version is retired. Everything you set up carries over.

What happens on the first run

When Abhoth starts and neither ABHOTH_HOME nor OPENORCA_HOME is set, it looks for ~/.abhoth. If that folder is missing, or holds nothing but logs, Abhoth copies ~/.openorca into it once:

  • Copied: config.json, sessions, prompts, projects and the web UI's sign-in data.
  • Left behind: logs, file checkpoints and config.json.bak* files.
  • Not changed: ~/.openorca itself. Nothing is moved or deleted, so you can go back.

The file formats are the same, so sessions saved by OpenOrca open in Abhoth, and the other way round.

Names

OpenOrcaAbhoth
openorcaabhoth (the same flags)
~/.openorca~/.abhoth
OPENORCA_HOME, OPENORCA_*ABHOTH_HOME, ABHOTH_*. The old names are still read as a fallback.
openorca --hostui-set-password <user>abhoth admin reset-password <user> (the old flag still works)

Some wire names keep "OpenOrca" for compatibility: the X-OpenOrca-Token header, the openorca MCP server name the bridges use, and the OpenOrca.Usage log category. ORCA.md project files and .orca/commands/ are unchanged too.

Docker

The Abhoth image still honours OPENORCA_HOME=/state/openorca, so an existing OpenOrca container's state is used as it is, with no migration step. /app/openorca is a symlink to /app/abhoth, so old docker exec commands keep working.

The old single sign-in account (webui/account.json) becomes the first admin of the new account system, with its password and two-factor setup. The file is left as it was.

What's different

  • One native binary instead of a .NET install, with the same behaviour. Parity was checked by running identical scenarios through both builds and comparing the output, then by a benchmark run: both builds passed 49 of 50 tasks, Abhoth took 0.98× the C# wall-clock time per task, and it spent 330 s outside model calls against C#'s 511 s.
  • New since the port: the desktop app with auto-update, the Windows installer, the router, native Ollama and Anthropic clients, and multi-user accounts in the web UI.
  • Where the C# build had bugs, a few were fixed rather than copied. One example: Ollama now gets the provider's context window instead of its small default.
