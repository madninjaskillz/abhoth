Local models

Abhoth was built for models you run yourself. Give it a base URL and it adapts to the server it finds.

Servers

ServerBase URLNotes
LM Studiohttp://localhost:1234/v1Start the local server. The context window is read from LM Studio.
llama.cpp (llama-server)http://localhost:8080/v1Use --jinja for native tool calls. Thinking levels map to its thinking switch and budget.
vLLM, ninfer and similarhttp://host:8000/v1The window is read from max_model_len.
Ollamahttp://localhost:11434Use a provider of type ollama (below) for the native API, so the context window is sent as num_ctx.
LiteLLM or abhoth routerthe gateway's /v1Detected as a gateway with several models.

Configure

{
  "lmStudio": {
    "baseUrl": "http://localhost:8080/v1",
    "apiKey": "none",
    "models": ["qwen3-coder-30b", "qwen3-8b"],
    "nativeToolCalling": true,
    "sampling": { "preset": "qwen-thinking-coding" }
  },
  "thinking": { "level": "low" },
  "context": { "contextWindowSize": 65536, "autoDetectContextWindow": true }
}
  • models are in priority order. If the first fails (a timeout, an empty reply, or a refusal with backupOnRefusal), Abhoth retries and then moves to the next.
  • nativeToolCalling sends tools through the API. If a server can't take them, Abhoth falls back to text tool calls for the rest of the session and rebuilds the prompt.
  • Sampling presets (qwen-thinking-coding, qwen-thinking-general, qwen-instruct) fill in only the settings you leave unset. modelSampling overrides them per model.
  • Vision: if a server refuses images, they're sent as file paths from then on, and you're told once.

Named providers

Add more servers under providers and use them for sub-agents, profiles or a project:

{
  "providers": {
    "ollama":  { "type": "ollama", "baseUrl": "http://localhost:11434",
                 "models": ["qwen3-coder:30b"], "contextWindow": 65536 },
    "claude":  { "type": "anthropic", "baseUrl": "https://api.anthropic.com",
                 "apiKeyEnv": "ANTHROPIC_API_KEY", "models": ["claude-sonnet-4-5"] },
    "gpu-box": { "type": "openai-compat", "baseUrl": "http://gpu-box:8000/v1",
                 "models": ["qwen3-coder-30b"] }
  }
}

Anthropic providers get prompt caching, effort and signed thinking. Keep keys out of the file with apiKeyEnv.

Choosing a model

Tool calling matters more than raw benchmark scores. Recent Qwen coder models work well and are the most tested. As a rough guide, 30B-class models handle multi-file features well, and 7B-14B models are fine for focused edits with a careful prompt. Give the model as much context as your hardware allows; 32k is a practical minimum and 64k or more is comfortable.

Inference slots and sub-agents

On a server with several parallel slots, or several copies of a model on different GPUs, Abhoth can lease a slot for the Lead and for each sub-agent:

  • The Lead keeps its slot, so its long prompt stays in the server's prefix cache between turns.
  • Sub-agents are placed on free copies and never share the Lead's copy, so delegated work runs in parallel without slowing the Lead.
  • agent.maxConcurrent limits parallel agents. The Lead delegates only when there's spare capacity.

Slots are configured under slots in config.json, or by a profile from a profile server (--profile). With several GPUs, put the router in front to handle leases, affinity and Lead priority on the server side.
