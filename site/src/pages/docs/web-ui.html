Web UI

abhoth --hostui serves a full web UI for your projects. Use it on your own machine, or on a server you reach from any browser.

Start it

abhoth --hostui                       # http://127.0.0.1:8192, a link with a token is printed
abhoth --hostui --hostui-open         # and open the browser
abhoth --hostui=0.0.0.0:8093 --hostui-login   # on the network, with sign-in

On your own machine, the printed link signs you in. It carries a one-time launch token; keep it to yourself. On a fresh install without a model, the UI still starts: open Settings, LLM Server, and set the base URL and models.

What's in it

  • Projects as tabs. Add a folder, create one, or clone from GitHub. Each project has its own session, profile and agent mode.
  • The chat shows thinking (collapsed), every tool call with its arguments, result and timing, and the final answer as Markdown. It also handles approvals and the agent's questions.
  • Agents as bars or tabs: the Lead and each sub-agent, with progress and the model they run on.
  • The file tree marks changed (M), new (U) and agent-touched files, and updates as files change.
  • Editor tabs with syntax highlighting, side-by-side diffs against git, and Save.
  • Terminals (real PTYs) and an HTML preview tab with back, forward and reload.
  • Engines: switch a project between Native, Claude Code and Codex.
  • Settings you can search, per project or as server defaults; most changes apply to the running session at once.
  • Benchmarks (with --hostui-bench): queue runs across models and modes, watch them live, and compare the results.

Accounts and sign-in

Multi-user accounts arrive in v0.16.2. Earlier versions have a single sign-in account, which becomes the first admin when you upgrade.

The first time the UI starts, it asks you to create an admin, using the setup code from the printed link. On a headless server, create the admin from the command line instead:

abhoth admin create <name>           # asks for the password twice
abhoth admin list
abhoth admin reset-password <name>   # also ends that user's sessions
abhoth admin reset-2fa <name>
  • Users have their own projects and chats. Admins manage users, server settings, the shared GitHub sign-in and the benchmarks, and read the audit log.
  • Passwords are hashed with Argon2id and must be 12 to 1024 characters, with no composition rules. Repeated failures back off.
  • Two-factor: TOTP with ten recovery codes. --hostui-require-2fa makes it mandatory.
  • API keys (abk_…) for scripts, sent as Authorization: Bearer. They're shown once, stored hashed, and can be revoked.
  • Sessions are server-side, with HttpOnly SameSite cookies. They end after 12 hours idle or 7 days.

Accounts separate users inside the web UI, not in the operating system. Agents run shell commands as the server's OS user, so give accounts only to people you'd trust with a shell on that machine.

Exposing it safely

--hostui-login marks a server as exposed. On an exposed server, the launch token only unlocks the first-run setup, and plain HTTP is refused except from the machine itself. Put it behind a reverse proxy that terminates HTTPS, and pass --hostui-trust-proxy=<proxy ip> so forwarded headers are trusted from that proxy only. The Docker image does this for you.
