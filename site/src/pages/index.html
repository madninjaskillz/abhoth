The coding agent for the models you run.

Abhoth reads your code, edits it, runs the tests and keeps going until the job is done. Point it at LM Studio, llama.cpp, vLLM, Ollama or any OpenAI-compatible server. Use it in the terminal, in the browser, as a desktop app, or on your own server.

Features

A whole agent harness, tuned for models you host.

Local models make different mistakes from cloud ones. Abhoth's loop is built around that: it repairs broken tool calls, notices when a model is going round in circles, keeps long sessions inside the context window, and hands work to sub-agents when there is spare capacity.

An agent loop that copes

Native and text tool calls, with JSON repair. It catches doom loops, runaway thinking and empty replies, and retries or fails over to your backup model when one stalls.

Dozens of built-in tools

Files, search, edit and patch; shell with background processes; git and GitHub; web fetch and search; archives; LSP; image generation; and any MCP server you add.

Sub-agents and a Lead

A Lead plans and delegates to sub-agents that run in parallel across your inference server's slots, with a planner phase, early read-only runs and optional pair voting.

Terminal, browser, desktop

An interactive terminal session, one-shot --print runs with JSON output for scripts, a full web UI with --hostui, and the same UI as a desktop app with a tray icon.

You stay in control

Tools are graded by risk and ask before they act. Allow and deny patterns like Bash(git *), a read-only plan mode, a sandbox mode, and a checkpoint of every file before it changes.

Engines and providers

OpenAI-compatible servers, native Ollama and the Anthropic Messages API. Claude Code and Codex can also run as engines, all inside the same project.

Sessions that last

Auto-saved sessions you can continue, resume, fork and browse as a tree. Compaction summarises old turns before the context window fills, and hooks can run before or after any tool.

Accounts for the web UI new

Multi-user sign-in for a shared server: Argon2id passwords, TOTP two-factor, API keys, per-user projects and an audit log. From v0.16.2.

Bridge mode coming soon

Start a session on your server and run its tools on your own laptop or GPU box. The server keeps the conversation; the machine is a remote pair of hands, limited to the folders you allow.

Web UI

Run abhoth --hostui and open the link. Every project gets a file tree with git status, a chat with each tool call laid out, editor tabs with diffs, real terminals and an HTML preview. Settings are searchable and apply to the running session.

Install

Up and running in a minute.

Version {{version}}. The installers come from GitHub Releases, with SHA-256 checksums.

Windows (x64)

One click, no admin rights. The installer puts abhoth.exe and the desktop app in your user folder, adds them to your PATH and a Start-menu shortcut, then opens the app. It updates itself in the background.

Download for Windows setup.exe Portable .zip

The builds are not code-signed yet, so SmartScreen may warn the first time: choose More info, then Run anyway. Uninstall from Settings, Apps.

Linux (x86-64)

An AppImage of the desktop app that updates itself. It needs WebKitGTK 4.1, which most desktop distributions already have. For the terminal agent on its own, build from source.

Download the AppImage 
chmod +x Abhoth.AppImage
./Abhoth.AppImage

On a server with no desktop, use Docker or build from source.

macOS

There's no macOS installer yet. CI builds and checks the desktop app on macOS, so building from source works:

git clone https://github.com/madninjaskillz/abhoth
cd abhoth
cargo build --release --features desktop
./target/release/abhoth --version

You need rustup; it installs the toolchain the repo pins.

Build from source

Any platform with Rust. The web client ships prebuilt in the repo, so you don't need Node.

git clone https://github.com/madninjaskillz/abhoth
cd abhoth
cargo build --release                      # target/release/abhoth
cargo build --release --features desktop   # adds --desktop and abhoth-desktop

On Linux, the desktop feature needs libwebkit2gtk-4.1-dev, libgtk-3-dev, libdbus-1-dev and pkg-config.

Docker: the web UI on your server

Build the image from the repo, then run it with sign-in turned on. See Self-host with Docker for volumes, secrets and a reverse proxy.

git clone https://github.com/madninjaskillz/abhoth
cd abhoth
docker build -f deploy/docker/Dockerfile -t abhoth-web .

Self-host it

Your own coding agent server.

Run Abhoth on the box that sits next to your GPUs and use it from any browser, including your phone. The Docker image is hardened by default and keeps all its state in one volume.

  • Sign-in mode for exposed servers: plain HTTP is refused except from the machine itself, and HTTPS works through your reverse proxy.
  • Runs locked down: as a non-root user, with a read-only root filesystem, no capabilities and only the project and state folders writable.
  • Git that works: deploy keys or a credential file as secrets, plus "Clone from GitHub" through a GitHub App.
  • A benchmark page: queue runs, compare models and modes, and watch them live.
Read the Docker guide 
# compose.yaml (minimal)
services:
  abhoth:
    image: abhoth-web
    restart: unless-stopped
    ports: ["8093:8093"]
    environment:
      PORT: "8093"
      ADMIN_USER: admin
    volumes:
      - ./projects:/projects
      - ./state:/state
      - ./admin-password:/run/secrets/admin-password:ro
    read_only: true
    tmpfs: [/tmp]
    cap_drop: [ALL]
    security_opt: ["no-new-privileges:true"]

Desktop app

The web UI in its own window.

abhoth --desktop starts the server on loopback and opens it in a native window, using WebView2 on Windows and WebKitGTK on Linux. There's no token to copy and no browser tab to lose.

  • Closing the window hides it to the tray. Your agents keep running; Quit from the tray when you're done.
  • One instance. Launching it again brings the window back.
  • Native folder picker, and links open in your normal browser.
  • Auto-update: it checks for a new release every 6 hours and offers "restart into" from the tray.

Local models

Built for the models on your own hardware.

Set a base URL and a model, and Abhoth works out the rest: the server's real context window, whether the model does native tool calls, and how to keep a long task inside its limits.

  • Any OpenAI-compatible server: LM Studio, llama.cpp, vLLM, ninfer, LiteLLM; plus native Ollama and the Anthropic API as named providers.
  • Context aware: reads the window from the server, compacts early and retries once after an overflow.
  • Thinking control: per-request thinking levels and budgets, sampling presets for Qwen-family coders, and a guard that stops runaway reasoning.
  • Backup models in priority order, with failover on timeouts, empty replies or refusals.
  • Inference slots: Abhoth leases slots on multi-slot servers, keeps the Lead's prompt cache warm and puts sub-agents on free copies.
Set up a local model 
# ~/.abhoth/config.json
{
  "lmStudio": {
    "baseUrl": "http://localhost:1234/v1",
    "models": ["qwen3-coder-30b", "qwen3-8b"],
    "nativeToolCalling": true
  },
  "providers": {
    "ollama": {
      "type": "ollama",
      "baseUrl": "http://localhost:11434",
      "models": ["qwen3-coder:30b"],
      "contextWindow": 65536
    }
  }
}

Routing

One endpoint in front of all your engines.

abhoth router is an OpenAI-compatible gateway built into the same binary. Clients see one URL and a list of model names. Behind it, the router picks a card, keeps sessions where their cache is warm and smooths over each engine's quirks.

  • Aliases and pinning: a model name can mean the whole pool, one card, or a catalog model.
  • Slot leases and Lead priority: the Lead always has a lane, and agents queue instead of hitting a 429.
  • Session affinity by prompt-cache key, so prefix caches keep hitting.
  • Per-engine fixes: it clamps reasoning effort, handles thinking-off, drops parameters an engine rejects, and fails over before the first byte.
  • Metrics: Prometheus /metrics, a /status JSON and a JSONL request log with no bodies. import-litellm converts an existing LiteLLM config.

The router is new and still on trial. Read the router docs.

Performance

Parity, with less overhead.

Abhoth is a careful port of the C# OpenOrca, checked against it scenario by scenario. Before the switch, both builds ran 100 benchmark runs on the same tasks, model and slots. Both passed 49 of 50 tasks, and Abhoth took 0.98× the C# wall-clock time per task (geometric mean).

To be straight about it, a coding agent spends nearly all its time waiting for the model, and a rewrite can't make the model faster. What Rust cuts is the harness's own time between model calls. Over the whole bench, that was 330 s for Abhoth against 511 s for C#.

Coming from OpenOrca?

Abhoth is OpenOrca, rewritten in Rust and renamed. The C# version is retired. The first time Abhoth starts, it copies your ~/.openorca folder to ~/.abhoth: config, sessions, prompts and projects, in the same file formats. It leaves the original untouched.

OPENORCA_* environment variables still work as a fallback, and existing Docker state is used as it is. Read the migration notes.

FAQ

Questions, answered.

Is Abhoth free?

Yes. It's open source under the MIT licence, with no paid tier and no account to create. You bring the model: one you run yourself, or an API you already pay for.

Does it send my code anywhere?

Only to the model servers you configure. There's no telemetry. The installed desktop app checks GitHub Releases for updates, and the agent reaches the web only through tools you allow, such as web fetch. Run a local model and your code never leaves your network.

Which models work best?

Any model with good tool calling. It's tuned and tested most with Qwen-family coding models served by llama.cpp, vLLM-style servers and LM Studio. Abhoth detects native tool calling, and falls back to text tool calls with repair for models that don't support it.

Can I use cloud models too?

Yes. Any OpenAI-compatible endpoint works, the Anthropic Messages API is supported natively (with prompt caching), and Claude Code or Codex can run as the engine of a project if you have them installed.

Is there a macOS build?

Not as an installer yet. CI builds and checks it on macOS, so build it from source with Cargo. The installers are for Windows (x64) and Linux (x86-64 AppImage).

Why does Windows warn about the installer?

The builds aren't code-signed yet, so SmartScreen doesn't know them. Every release lists SHA-256 checksums in SHA256SUMS, and you can always build the same code yourself.

Can several people share one server?

Yes. The web UI has accounts with roles, two-factor sign-in, API keys and per-user projects (from v0.16.2). Accounts separate users in the web UI, not in the operating system: agents run shell commands as the server's user, so only give accounts to people you'd trust with a shell.

Why "Abhoth"?

In Clark Ashton Smith's mythos, Abhoth is an ancient being that endlessly spawns offspring, which suits an agent that spawns sub-agents. Ours is friendlier, and wears a hood.
