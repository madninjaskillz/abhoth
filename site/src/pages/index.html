Your models, your hardware

Built for the model on your own GPU.

Most coding agents are designed around the biggest cloud models, and they struggle when you point them at something you run yourself. A local model might format a tool call slightly wrong, think for too long, or lose track halfway through a long task. A harness that assumes perfect behaviour gives up there, or wastes your evening going round in circles.

Abhoth expects this. It repairs tool calls that come back as broken JSON, notices when the model repeats itself, and stops runaway reasoning. It reads the server's real context window and summarises older turns before the window fills, so long tasks don't fall over. Set a base URL, whether that's LM Studio, llama.cpp, vLLM or Ollama, and it adapts to the server it finds.

Your code stays on your network, and you aren't paying per token to iterate.

A real agent

It doesn't stop at a suggestion.

Pasting code from a chat window into your editor gets old quickly. Abhoth works in the project itself. It reads the files it needs, makes the edit, runs your tests, and if something fails it reads the error and tries again. It finishes when the work is verified, and then tells you plainly what changed.

You stay in charge. Reading is free, but anything that writes files or runs commands asks first, unless you've allowed it with rules like Bash(npm test*). Every file is checkpointed before it changes, so /undo is always there. For bigger jobs, a Lead plans the work and hands parts of it to sub-agents that run in parallel.

Use it anywhere

One agent, wherever you work.

Some days you live in a terminal, and some days you want to see a diff, or check in on a long task from your phone. Abhoth is a single binary that does all of it. Run abhoth for an interactive session in the current folder, or abhoth -p "…" for one-shot runs in scripts and CI.

abhoth --hostui serves a full web UI. Projects open as tabs, each with a file tree that shows git changes, the chat with every tool call laid out, editor tabs with side-by-side diffs, and real terminals. abhoth --desktop puts the same UI in a native window. Closing the window hides it to the tray, so your agents keep working, and it updates itself in the background.

Self-host for a team

A coding agent server you own.

The GPUs are usually in one machine, and the people who want to use them are everywhere else. Run Abhoth in Docker next to the hardware, and everyone gets the same agent from their browser, without installing anything or copying model settings around.

It's built to sit on a network. Each person has their own account and projects, with optional two-factor sign-in and API keys for scripts. The container runs as a non-root user with a read-only filesystem and no extra privileges. Put it behind your usual HTTPS proxy and it's ready. There's even a benchmark page to compare models and settings on your own tasks.

Read the Docker guide → 
# compose.yaml
services:
  abhoth:
    image: abhoth-web
    restart: unless-stopped
    ports: ["8093:8093"]
    environment:
      PORT: "8093"
      ADMIN_USER: admin
    volumes:
      - ./projects:/projects
      - ./state:/state
      - ./admin-password:/run/secrets/admin-password:ro
    read_only: true
    tmpfs: [/tmp]
    cap_drop: [ALL]
    security_opt: ["no-new-privileges:true"]

Routing

Make several GPUs behave like one.

Once you have more than one card, or a mix of local models and a cloud API, every request needs to go somewhere sensible. Round-robin load balancing breaks prompt caches and lets background work take the lane your main conversation needs.

abhoth router is an OpenAI-compatible gateway in the same binary. It knows what a coding agent needs. It keeps each session on the card where its cache is warm, makes sure the lead conversation never waits behind its own sub-agents, and smooths over each engine's quirks so clients don't have to. Abhoth also talks to the Anthropic API and Ollama directly, and can run Claude Code or Codex as the engine of a project.

The router is new and still being trialled. Read the router docs.

Open source

Yours to read, run and change.

A tool that edits your code and runs commands should be one you can inspect. Abhoth is MIT licensed, with no paid tier, no account to create and no telemetry. It talks to the model servers you configure and the GitHub release feed for updates. It only goes further when you let the agent use a tool like web fetch.

It's written in Rust as one native binary, with nearly two thousand tests behind it. Next is bridge mode: start a session on your server and let it work on your laptop's files, limited to the folders you allow.

Install

Summon your own coding agent.

Version {{version}}, from GitHub Releases. Install it, point it at a model, and give it something to fix.

One click, no admin rights. The installer adds abhoth to your PATH and a Start-menu shortcut to the desktop app, which keeps itself up to date. The builds aren't code-signed yet, so SmartScreen may ask you to confirm the first time.

Download for Windows setup.exe Portable .zip

A self-updating AppImage of the desktop app for x86-64. It needs WebKitGTK 4.1, which most desktop distributions already have. On a headless server, use Docker.

Download the AppImage
chmod +x Abhoth.AppImage && ./Abhoth.AppImage

There's no macOS installer yet. CI builds and checks the desktop app on macOS, so building from source with rustup works:

git clone https://github.com/madninjaskillz/abhoth && cd abhoth
cargo build --release --features desktop

Any platform with Rust. The web client ships prebuilt, so you don't need Node.

git clone https://github.com/madninjaskillz/abhoth && cd abhoth
cargo build --release                      # target/release/abhoth
cargo build --release --features desktop   # adds --desktop

Build the image from the repo, then follow Self-host with Docker for volumes, accounts and HTTPS.

git clone https://github.com/madninjaskillz/abhoth && cd abhoth
docker build -f deploy/docker/Dockerfile -t abhoth-web .
